# 第 5 章　奖励模型（Reward Modeling）

> 译自 Nathan Lambert, *Reinforcement Learning from Human Feedback*（rlhfbook.com），2026-07-01 版，原文第 37–52 页。

奖励模型（reward model）是现代 RLHF 方法的核心，因为复杂的人类偏好正是在这里被学习的。它们让我们的模型得以从难以明确定义的信号中学习。它们把数据中的复杂特征压缩成一种可供下游训练使用的表示——这是一种再次展现现代深度学习强大能力的魔法。这些模型在后续章节所研究的核心优化中扮演代理目标（proxy objectives）的角色。如图 11 所示，奖励模型扮演着类似标准 RL 环境的角色，为智能体（agent）提供学习信号；但与固定不变的环境不同，我们得以从人类偏好中学习它。

奖励模型在强化学习研究中历来被广泛用作环境奖励的代理 [54]。其现代形式的奖励模型，最初是作为研究价值对齐问题（value alignment problem）的工具而被提出 [38]。这类模型通常接收某种形式的输入，并输出单一标量的奖励值。这个奖励可以有多种形式——在传统 RL 问题中，它试图逼近该问题的精确环境奖励；但我们将在 RLHF 中看到，奖励模型实际上输出的是某个输入「质量很高」的概率（亦即在成对偏好关系中被选择的答案）。RLHF 的奖励建模实践与逆向强化学习（inverse reinforcement learning）密切相关——后者的问题是在给定行为轨迹的情况下逼近智能体的奖励函数 [71]——也与深度强化学习的其他领域相关。两者高层次的问题陈述相同，但实现方式与研究重点完全不同，因此通常被视为完全独立的研究领域。

最常见的奖励模型通常称为 Bradley-Terry 奖励模型，也是本章的主要焦点；它预测的是一段文字相对于训练比较数据中的另一段文字「较受偏好」的概率。本章稍后我们也会将它与结果奖励模型（Outcome Reward Models, ORMs）、过程奖励模型（Process Reward Models, PRMs）以及其他类型的奖励模型进行比较。

*在本章中，我们用 $x$ 表示提示（prompt）、$y$ 表示补全（completion）。这种记号在语言模型文献中很常见，因为这些方法是在完整的提示—补全对上运作，而不是在个别 token 上。*

## 5.1 训练 Bradley-Terry 奖励模型（Training a Bradley-Terry Reward Model）

奖励模型的标准实现源自 Bradley-Terry 偏好模型 [72]。训练 RLHF 标准奖励模型有两种常见的表达方式——它们在数学上是等价的。首先，Bradley-Terry 偏好模型定义了在两个项目 $i$ 与 $j$ 的成对比较中，评审偏好 $i$ 胜过 $j$ 的概率：

$$P(i > j) = \frac{p_i}{p_i + p_j}. \tag{12}$$

![图](../webapp/assets/figures/fig-p038-1.png)
*图 11：RLHF 中的奖励模型扮演标准 RL 中返回奖励的环境组件角色。关键差异在于：在 RLHF 中，我们得以控制这个奖励函数，并从人类偏好中学习它，而不是由环境固定给定。*

Bradley-Terry 模型假设每个项目都有一个潜在强度（latent strength）$p_i > 0$，而观察到的偏好是这些底层强度带有噪声的反映。常见做法是以无界分数重新参数化 Bradley-Terry 模型，令 $p_i = e^{r_i}$，得到以下形式：

$$P(i > j) = \frac{e^{r_i}}{e^{r_i} + e^{r_j}} = \sigma(r_i - r_j). \tag{13}$$

其中 $\sigma(z) = \frac{1}{1+e^{-z}}$ 是逻辑斯函数（logistic function，即 sigmoid 函数），因此偏好概率只取决于分数差 $r_i - r_j$。只有分数之间的差异才重要：对每个 $r_k$ 加上相同的常数 $c$，$P(i > j)$ 保持不变。这些形式是人类偏好的一种有用近似，在 RLHF 中通常效果很好。

要训练奖励模型，我们必须构造一个满足上述关系的损失函数。实际应用中，这是透过将语言模型转换为输出标量分数的模型来完成，通常是加上一个小的线性头（linear head），从模型的最终隐藏状态（hidden state）产生单一奖励值。给定提示 $x$ 与两个采样得到的补全 $y_1$ 与 $y_2$，我们用奖励模型 $r_\theta$ 为两者评分，并将条件分数写作 $r_\theta(y_i \mid x)$。

奖励模型认为 $y_1$ 比 $y_2$ 更受偏好的概率变为：

$$P(y_1 > y_2 \mid x) = \frac{\exp\left(r_\theta(y_1 \mid x)\right)}{\exp\left(r_\theta(y_1 \mid x)\right) + \exp\left(r_\theta(y_2 \mid x)\right)}. \tag{14}$$

我们将较受偏好的补全记为 $y_c$（chosen，被选择），将被拒绝的补全记为 $y_r$（rejected，被拒绝）。

由此得到的损失会鼓励奖励模型给人类偏好的补全比被拒绝的补全更高的分数，并利用 sigmoid 将分数差转换为概率。式 (14) 中的偏好似然是出发点。我们先把该似然改写成 sigmoid 形式，方法是将分子与分母同除以 $\exp\left(r_\theta(y_c \mid x)\right)$：

$$
\begin{aligned}
P(y_c > y_r \mid x) &= \frac{\exp\left(r_\theta(y_c \mid x)\right)}{\exp\left(r_\theta(y_c \mid x)\right) + \exp\left(r_\theta(y_r \mid x)\right)} \\
&= \frac{\exp\left(r_\theta(y_c \mid x)\right)}{\exp\left(r_\theta(y_c \mid x)\right)\left(1 + \frac{\exp(r_\theta(y_r \mid x))}{\exp(r_\theta(y_c \mid x))}\right)} \\
&= \frac{1}{1 + \frac{\exp(r_\theta(y_r \mid x))}{\exp(r_\theta(y_c \mid x))}} \\
&= \frac{1}{1 + \exp\left(-(r_\theta(y_c \mid x) - r_\theta(y_r \mid x))\right)} \\
&= \sigma\left(r_\theta(y_c \mid x) - r_\theta(y_r \mid x)\right).
\end{aligned} \tag{15}
$$

接着，奖励模型是以最大似然（maximum likelihood）在偏好数据集 $D$ 上拟合的，即最大化观察到的偏好之期望对数似然。由于对数是单调函数，这等价于最小化期望负对数似然（negative log-likelihood）：

$$
\begin{aligned}
\theta^* &= \arg\max_\theta \mathbb{E}_{(x, y_c, y_r) \sim D}\left[\log P(y_c > y_r \mid x)\right] \\
&= \arg\min_\theta \mathbb{E}_{(x, y_c, y_r) \sim D}\left[-\log \sigma\left(r_\theta(y_c \mid x) - r_\theta(y_r \mid x)\right)\right].
\end{aligned} \tag{16}
$$

在对数据集取平均*之前*先取对数，正是负对数似然损失成为正确目标的关键：最大化期望概率 $\mathbb{E}[P]$ 与最大化期望对数概率 $\mathbb{E}[\log P]$ 并不相同。

每笔样本的损失就是上述期望值内的 log-sigmoid 表达式，如 [3] 与其他工作所示：

$$\mathcal{L}(\theta) = -\log\left(\sigma\left(r_\theta(y_c \mid x) - r_\theta(y_r \mid x)\right)\right) \tag{17}$$

第二种是数学上等价的形式，以 softplus 函数 $\log(1 + e^{x})$ 表达，如 [23] 与其他工作所示：

$$\mathcal{L}(\theta) = \log\left(1 + e^{r_\theta(y_r \mid x) - r_\theta(y_c \mid x)}\right) \tag{18}$$

两者的等价性可透过令 $\Delta = r_\theta(y_c \mid x) - r_\theta(y_r \mid x)$ 并利用 $\sigma(\Delta) = \frac{1}{1+e^{-\Delta}}$ 得出，这意味着 $-\log \sigma(\Delta) = \log(1 + e^{-\Delta}) = \log\left(1 + e^{r_\theta(y_r \mid x) - r_\theta(y_c \mid x)}\right)$。这两种形式都出现在 RLHF 文献中。

![图](../webapp/assets/figures/fig-p040-1.png)

## 5.2 默认的奖励模型架构（The Default Reward Model Architecture）

奖励模型最常见的实现方式，是透过类似 Transformers 函数库 `AutoModelForSequenceClassification` 的抽象——它在语言模型上附加一个小的线性头，于训练或推论时为提示—补全对产生一个标量奖励分数。在推论时，模型以模型输出的单一 logit 表示*该段文字被选择的相对可能性*。

也存在其他实现选项，例如直接从最终嵌入（embeddings）接一个线性层，但这些在开源工具中较不常见。

## 5.3 实现范例（Implementation Example）

实现奖励建模损失相当简单。实现上的挑战更多在于建立独立的数据加载器（data loader）与推论管线。给定正确的数据加载器（含分词后的被选择与被拒绝的提示与补全），损失的实现如下：

```python
import torch.nn as nn
# inputs_chosen / inputs_rejected 包含提示 token x 以及各自的
# 补全 token（y_c 或 y_r），奖励模型会对两者一并评分。
rewards_chosen = model(**inputs_chosen)
rewards_rejected = model(**inputs_rejected)
loss = -nn.functional.logsigmoid(rewards_chosen - rewards_rejected).mean()
```

就更大的图景而言，这通常位于一个因果语言模型（causal language model，即由左至右生成 token、以所有先前 token 为条件预测每个 token 的模型）之内，该模型加上（并以上述损失学习）一个额外的头，将最终隐藏状态转换为输入的分数。代码接收标准的 transformer 输入——`input_ids`（分词后的文字）与 `attention_mask`（标记哪些是真实 token、哪些是填充 token）——并在最后一个真实 token 处提取隐藏状态（模型对输入的内部表示），再通过一个线性层产生标量奖励。这个模型的结构如下：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class BradleyTerryRewardModel(nn.Module):
    """
    用于 Bradley-Terry 偏好学习的标准标量奖励模型。

    用法（成对 BT 损失）：
        rewards_chosen = model(**inputs_chosen)    # (batch,)
        rewards_rejected = model(**inputs_rejected)  # (batch,)
        loss = -F.logsigmoid(rewards_chosen - rewards_rejected).mean()
    """
    def __init__(self, base_lm):
        super().__init__()
        self.lm = base_lm  # 例如 AutoModelForCausalLM
        self.head = nn.Linear(self.lm.config.hidden_size, 1)

    def _sequence_rep(self, hidden, attention_mask):
        """
        为每个序列取得一个用于评分的向量。
        默认：最后一个非填充 token（EOS token）；若无遮罩，则取最后一个 token。
        hidden: (batch, seq_len, hidden_size)
        attention_mask: (batch, seq_len)
        """

        # 每个序列中最后一个非填充 token 的索引
        # attention_mask 对真实 token 为 1，对填充为 0
        lengths = attention_mask.sum(dim=1) - 1  # (batch,)
        batch_idx = torch.arange(hidden.size(0), device=hidden.device)
        return hidden[batch_idx, lengths]  # (batch, hidden_size)

    def forward(self, input_ids, attention_mask):
        """
        此前向传递旨在展示标准奖励模型的推论结构。
        若要训练，需修改此函数以同时计算被选择与被拒绝输入的奖励，
        并套用上述损失。
        """
        outputs = self.lm(
            input_ids=input_ids,
            attention_mask=attention_mask,
            output_hidden_states=True,
            return_dict=True,
        )
        # 最终隐藏状态：(batch, seq_len, hidden_size)
        hidden = outputs.hidden_states[-1]

        # 每个序列一个标量奖励：(batch,)
        seq_repr = self._sequence_rep(hidden, attention_mask)
        rewards = self.head(seq_repr).squeeze(-1)

        return rewards
```

在本节以及后续内容中，奖励模型（乃至大部分后训练）的实现复杂度多半集中在正确建构数据加载器与分布式学习系统。注意，训练奖励模型时，最常见的做法是只训练 1 个 epoch，以避免过度拟合（overfitting）。

## 5.4 奖励模型变体（Reward Model Variants）

奖励建模在 RLHF 中是一个相对较少被探索的领域。传统的奖励建模损失在许多知名工作中被修改过，但这些修改尚未凝聚为单一的最佳实践。

### 5.4.1 偏好边际损失（Preference Margin Loss）

当标注者提供的是李克特量表（Likert Scale，一种具有顺序类别、能表示偏好强度的评分量表，例如 1–5）上的分数或排名时，这些相对量的大小可以用于训练。最常见的做法是沿着偏好方向将数据二值化，把相对评分或排名强度的混合信息化约为只有被选择与被拒绝的补全。额外的信息——例如偏好的强度——曾被用来改进模型训练，但尚未成为标准做法。Llama 2 提出使用两个数据点之间的边际（margin）$m(y_c, y_r)$ 来区分偏好的强度：

$$\mathcal{L}(\theta) = -\log\left(\sigma\left(r_\theta(y_c \mid x) - r_\theta(y_r \mid x) - m(y_c, y_r)\right)\right) \tag{19}$$

举例来说，每个补全通常会依质量得到 1 到 5 的排名。若被选择的样本得分为 5、被拒绝的样本得分为 2，则边际 $m(y_c, y_r) = 5 - 2 = 3$。也可以探索其他计算边际的函数。

注意，在 Llama 3 中这个边际项被移除了，因为团队观察到在规模扩大后改进递减。

### 5.4.2 平衡每个提示的多重比较（Balancing Multiple Comparisons Per Prompt）

InstructGPT 研究了对每个提示使用 $K = 4$ 到 9 个补全进行排名的影响，从每个提示产生 $\binom{K}{2}$ 个成对比较 [3]。由于这些比较高度相关（它们共享相同的提示），天真地将它们洗牌混入数据集会使奖励模型过度拟合。为了解决这个问题，他们对每个提示的每个比较加权其损失更新——若不重新加权，补全较多的提示只因产生更多配对就会贡献更多总损失。实际应用中，来自单一提示的所有 $\binom{K}{2}$ 个比较通常会被放进同一个训练批次并一起平均，如此每个提示贡献一次分组更新，而不是分散在许多独立批次中。这减少了对个别提示的过度拟合，并防止采样补全较多的提示主导损失。损失函数变为：

$$\mathcal{L}(\theta) = -\frac{1}{\binom{K}{2}} \mathbb{E}_{(x, y_c, y_r) \sim D} \log\left(\sigma\left(r_\theta(y_c \mid x) - r_\theta(y_r \mid x)\right)\right) \tag{20}$$

### 5.4.3 K-wise 损失函数（K-Wise Loss Function）

还有许多其他公式可以建立适用于 RLHF 的人类偏好模型。其中一个例子是基于 Plackett-Luce 模型 [74] 的 K-wise 损失函数，曾被用于知名的早期 RLHF 模型 Starling 7B 与 34B [73]。

Zhu et al. 2023 [75] 将该设定形式化如下。给定一个提示（或状态）$s^i$，从 $P(a_0, \cdots, a_{K-1} \mid s^i)$ 采样 $K$ 个动作 $(a_0^i, a_1^i, \cdots, a_{K-1}^i)$。接着，标注者依偏好对这 $K$ 个动作排序，产生一个排列 $\sigma^i : [K] \mapsto [K]$，其中 $\sigma^i(0)$ 是最受偏好的动作。这产生了对所有 $K$ 个项目完整排名的 Plackett-Luce 概率：

$$P(\sigma^i \mid s^i, a_0^i, a_1^i, \ldots, a_{K-1}^i) = \prod_{k=0}^{K-1} \frac{\exp\left(r_{\theta\star}(s^i, a_{\sigma^i(k)}^i)\right)}{\sum_{j=k}^{K-1} \exp\left(r_{\theta\star}(s^i, a_{\sigma^i(j)}^i)\right)} \tag{21}$$

当 $K = 2$ 时，这退化为用于成对比较的 Bradley-Terry（BT）模型。无论如何，一旦训练完成，这些模型在 RLHF 训练期间的使用方式与其他奖励模型类似。

## 5.5 结果奖励模型（Outcome Reward Models）

语言模型与其他 AI 系统的大部分*偏好微调*（preference tuning）都是以上面讨论的 Bradley-Terry 模型完成的。对于重推理的任务，可以使用结果奖励模型（Outcome Reward Model, ORM）。ORM 的训练数据以类似标准偏好微调的方式建构。这里我们有一个问题陈述或提示 $x$，以及两个补全 $y_1$ 与 $y_2$。此处使用的归纳偏置（inductive bias）是：其中一个补全应为该问题的正确解，另一个为错误解，形成 $(y_c, y_{ic})$。

所使用的模型架构与标准奖励模型非常相似，都是在能输出单一 logit 的模型上附加一个线性层（就 RM 而言）——而在 ORM 中，后续的训练目标略有不同 [76]：

> [我们]以联合目标训练验证器（verifier），模型除了原本的语言建模目标之外，还要学习将模型补全标记为正确或错误。在架构上，这意味着我们的验证器是语言模型，加上一个小的标量头，以逐 token 的方式输出预测。我们将这个标量头实现为单一偏置参数与单一增益参数，作用于语言模型最终反嵌入层（unembedding layer）输出的 logits 上。

换句话说，这被实现为一个语言建模头，能对每个 token 预测两个类别（1 为正确、0 为错误），而不是传统 RM 那种对整个序列输出一个 logit 的分类头。形式上，依循 [77]，这是一个逐 token 的二元交叉熵（binary cross-entropy）损失：

$$\mathcal{L}_{\text{CE}}(\theta) = -\mathbb{E}_{(s, r) \sim \mathcal{D}}\left[r \log p_\theta(s) + (1 - r)\log\left(1 - p_\theta(s)\right)\right] \tag{22}$$

其中 $r \in \{0, 1\}$ 是二元标签，1 对应给定提示的正确答案、0 对应错误答案，而 $p_\theta(s)$ 是与被训练模型所预测的正确概率成比例的标量。在代码中，这个结果标签会被复制到每个补全 token 上，而提示 token 以 `-100` 遮罩，因此不会对损失有所贡献。

实现结果奖励模型（以及其他类型，如我们稍后在过程奖励模型中会看到的）需要根据补全是否为正确样本，以逐 token 的方式套用交叉熵损失。这远比较接近语言建模损失——它不需要标准 Bradley-Terry 奖励模型那种结构化的 chosen-rejected 性质。在下面简化的 ORM 训练设定中，我们不会采样新的 token，也不会以下一个 token 预测来训练 LLM；我们将固定的提示—补全序列喂入骨干网络（backbone），并训练 ORM 头来预测正确性标签。

模型结构可以如下：

```python
import torch.nn as nn
import torch.nn.functional as F

class OutcomeRewardModel(nn.Module):
    def __init__(self, base_lm):
        super().__init__()
        self.lm = base_lm  # 例如 AutoModelForCausalLM
        self.head = nn.Linear(self.lm.config.hidden_size, 1)

    def forward(self, input_ids, attention_mask=None, labels=None):
        """
        input_ids 包含完整的提示+补全序列。
        labels 与 token 对齐：提示 token 为 -100，且每个补全
         token 重复整个序列的结果标签（1=正确，0=错误）。
        若 labels=None，这是仅推论的前向传递，损失以 None
         返回。
        """
        outputs = self.lm(
            input_ids=input_ids,
            attention_mask=attention_mask,
            output_hidden_states=True,
            return_dict=True,
        )
        # 最终隐藏状态：(batch, seq_len, hidden_size)
        hidden = outputs.hidden_states[-1]
        # 每个 token 一个标量 logit：(batch, seq_len)
        logits = self.head(hidden).squeeze(-1)

        # 仅推论的前向传递：不计算损失。
        if labels is None:
            return None, logits
        # 只在补全 token（标签为 0 或 1）上计算损失
        # 提示 token 的标签为 -100
        mask = labels != -100
        loss = None
        if mask.any():
            loss = F.binary_cross_entropy_with_logits(
                logits[mask], labels[mask].float()
            )
        else:
            loss = logits.sum() * 0
        return loss, logits
```

损失的简化版本如下：

```python
# 将完整的提示+补全序列一次喂入；此处不进行任何 token 采样。
# 假设模型已具备：model.lm（骨干网络）+ model.head
hidden = model.lm(**inputs, output_hidden_states=True).hidden_states[-1]
logits_per_token = model.head(hidden).squeeze(-1)  # (batch, seq_len)
# 在其他实现中，这有时会被压缩为 model.forward()

# 二元标签：1=正确，0=错误（提示 token 以 -100 遮罩）
mask = labels != -100
loss = F.binary_cross_entropy_with_logits(
    logits_per_token[mask], labels[mask].float()
)
```

这里的重要直觉是：ORM 会在序列的每个 token 上输出一个正确性概率（仅以最终答案来评判——推理错误不会在 ORM 的训练过程中被捕捉到）。这可能是一个带噪声的过程，因为更新与损失会依结果与注意力映射（attention mappings）逐 token 传播。

![图](../webapp/assets/figures/fig-p045-1.png)
*图 13：推论时，结果奖励模型会对补全 token 输出逐 token 的正确性概率。提示 token 不参与评分，而补全概率可以汇总为回应层级的分数，用于验证、过滤或重新排序。*

这些模型持续被使用，但在开源 RLHF 工具中的支持较少。举例来说，开创性工作 *Let's Verify Step by Step* [50] 使用了同类型的 ORM，但去掉了损失中的语言建模预测部分。此时最终损失是对每个 token 的交叉熵损失，预测最终答案是否正确。

由于缺乏支持，结果奖励模型（ORM）一词被以多种方式使用。有些文献（例如 [77]）继续沿用 Cobbe et al. 2021 的原始定义；其他人则更广义地用它来指任何被训练来预测补全是否正确的验证器。

## 5.6 过程奖励模型（Process Reward Models）

过程奖励模型（Process Reward Models, PRMs），最初称为过程监督奖励模型（process-supervised reward models），是被训练来在思维链（chain-of-thought）推理过程的每个*步骤*输出分数的奖励模型。这与只在 EOS token 输出分数的标准 RM、或在每个 token 输出分数的 ORM 不同。过程奖励模型需要在每个推理步骤结尾提供监督，然后以类似方式训练，其中步骤内的 token 会被训练到其相关目标——PRM 的目标是该步骤，而 ORM 的目标是整个回应。

![图](../webapp/assets/figures/fig-p046-1.png)
*图 14：训练结果奖励模型使用来自验证器或数据集的离线标签（例如正确补全全为 1）。每个补全 token 以二元交叉熵针对结果标签进行训练，逐 token 概率再汇总为最终分数，用于验证、过滤或重新排序。*

依循 [50]，二元标签的 PRM 通常以逐步骤的交叉熵损失优化：

$$\mathcal{L}_{\text{PRM}}(\theta) = -\mathbb{E}_{(x, s) \sim \mathcal{D}}\left[\sum_{i=1}^{K} y_{s_i} \log r_\theta(s_i \mid x, s_{<i}) + (1 - y_{s_i})\log\left(1 - r_\theta(s_i \mid x, s_{<i})\right)\right] \tag{23}$$

其中 $s$ 是含有 $K$ 个标注步骤的采样思维链，$y_{s_i} \in \{0, 1\}$ 表示第 $i$ 个步骤是否正确，而 $r_\theta(s_i \mid x, s_{<i})$ 是 PRM 在给定原始提示 $x$ 与所有先前步骤 $s_{<i}$ 的条件下，预测步骤 $s_i$ 有效的概率。

以下是这种逐步骤标签如何在训练器中封装的范例，来自 HuggingFace 的 TRL（Transformer Reinforcement Learning）[47]：

```python
# 取得分隔 token 的 ID 并将其加到补全的尾端
separator_ids = tokenizer.encode(step_separator, add_special_tokens=False)
completions_ids = [completion + separator_ids for completion in completions_ids]

# 建立标签
labels = [[-100] * (len(completion) - 1) + [label] for completion, label in
zip(completions_ids, labels)]
```

传统上，PRM 以语言建模头训练，只在推理步骤结尾的 token 产生输出，例如对应双换行或其他特殊 token 的位置。这些预测通常是 -1 代表错误、0 代表中性、1 代表正确。这些标签不必然对应模型是否走在正确的路径上，而是该步骤本身是否正确。

下面展示 PRM 的一个建构范例。

![图](../webapp/assets/figures/fig-p047-1.png)
*图 15：过程奖励模型仅在步骤边界（例如换行 token）提供监督。每个步骤会得到一个三类标签：正确（+1）、中性（0）或错误（-1）。训练期间，其他所有 token 都会被遮罩。*

```python
import torch.nn as nn
import torch.nn.functional as F

class ProcessRewardModel(nn.Module):
    def __init__(self, base_lm, num_classes=3):
        super().__init__()
        self.lm = base_lm  # 例如 AutoModelForCausalLM
        self.head = nn.Linear(self.lm.config.hidden_size, num_classes)

    def forward(self, input_ids, attention_mask=None, labels=None):
        """
        输入是分词后的提示与补全，其中「推理步骤」的结尾
         由指定的分隔 token 标示，例如换行或其他特殊标记，
         而非批次填充。
        labels 是一组标签：True、False 与 Neutral（3 种标签），
         由模型进行预测。
        若 labels=None，这是仅推论的前向传递，损失以 None
         返回。
        """
        outputs = self.lm(
            input_ids=input_ids,
            attention_mask=attention_mask,
            output_hidden_states=True,
            return_dict=True,
        )
        # 最终隐藏状态：(batch, seq_len, hidden_size)
        hidden = outputs.hidden_states[-1]
        # 每个 token 一个 logit 向量：(batch, seq_len, num_classes)
        logits = self.head(hidden)

        # 仅推论的前向传递：不计算损失。
        if labels is None:
            return None, logits
        # 只在步骤边界（labels != -100 之处）计算损失
        # 标签映射：-1 -> 0，0 -> 1，1 -> 2（类别索引）
        mask = labels != -100
        loss = None
        if mask.any():
            loss = F.cross_entropy(
                logits[mask], labels[mask]
            )
        else:
            loss = logits.sum() * 0
        return loss, logits
```

其核心损失函数看起来与结果奖励模型非常相似，只是标签套用的间隔不同。

```python
# 假设模型对每个 token 输出三类 logits
hidden = model.lm(**inputs, output_hidden_states=True).hidden_states[-1]
logits = model.head(hidden)  # (batch, seq_len, 3)

# 仅在步骤边界处的三类标签：0=-1、1=0、2=1（其余以 -100 遮罩）
mask = labels != -100
loss = F.cross_entropy(logits[mask], labels[mask])
```

## 5.7 各类奖励模型（与价值函数）之比较（Comparing Reward Model Types (and Value Functions)）

前面涵盖的各类奖励模型，展示了 RLHF 与其他后训练方法中「质量」可以被衡量的方式光谱。下面是这些模型预测什么以及如何训练的摘要。

表 2：各类奖励模型之比较。

| 模型类别 | 预测什么 | 如何训练 | LM 结构 |
|---|---|---|---|
| **奖励模型** | 序列层级的质量分数 $r_\theta(x, y)$ | 补全之间成对（或 N-wise）比较的对比损失 | 在 EOS／最后 token 隐藏状态上的线性头 |
| **结果奖励模型** | 答案正确的逐 token 概率 | 带标签的结果对（例如可验证领域上的成功／失败） | 逐 token 二元交叉熵头；标签重复结果标签 |
| **过程奖励模型** | 推理步骤结尾处对中间步骤的奖励或分数 | 使用中间反馈或逐步标注训练（对推理步骤中的每个 token 训练） | 预测步骤正确性（-1、0、1）的逐 token 头 |
| **价值函数** | 给定当前状态的期望回报 | 透过对序列中每个点的回归训练 | 具逐 token 输出的标量回归头 |

关于此表中区分方式的几点注意事项，因为各模型类型之间的界线并不总是泾渭分明：

- 无论在偏好微调或推理训练中，价值函数通常使用折扣因子（discount factor）1，这使得价值函数更接近结果奖励模型，但训练损失不同。
- 过程奖励模型可以透过从某个中间状态进行推演（rollout）并收集结果数据来提供监督。这混合了多种想法，但只要*损失*使用逐推理步骤的标签，最好仍称之为 PRM。

**如果你用正确／错误配对来训练 Bradley-Terry 成对模型会怎样？** 关于结果奖励模型的许多混淆，来自一小部分在源自答案正确性的成对数据上训练奖励模型的文献。在这种情境下，你把被选择的回应设为某问题的正确答案，把被拒绝的回应设为*同一问题*的错误答案。这在技术上不是 ORM，且仍然直接以对比式、序列层级的损失训练。这在技术上仍是 Bradley-Terry 模型，会落在我们涵盖的第一类模型中。

**ORM vs. 价值函数。** ORM 与价值函数可能看起来相似，因为两者都以相同的头架构产生逐 token 输出，但它们在*预测什么*与*目标从何而来*上有所不同：

- **ORM** 预测即时的、token 局部的量：$p(\text{correct}_t)$ 或 $r_t$。目标来自*离线标签*（将 token／序列标记为正确或错误的验证器或数据集）。
- **价值函数**预测期望的*剩余*回报：$V(s_t) = \mathbb{E}\left[\sum_{k \geq t} \gamma^{k-t} r_k \mid s_t\right]$。目标通常是*从当前策略 $\pi_\theta$ 的 on-policy 推演计算而来*，并随策略改变而变化（技术上，价值函数也可以是 off-policy 的，但这在语言建模的工作中尚未确立）。

如果你定义密集的 token 奖励 $r_t = \mathbb{1}[\text{token 正确}]$ 并使用 $\gamma = 1$，那么 ORM 学习的是 $r_t$（或 $p(r_t = 1)$），而价值头学习的是剩余总和 $\sum_{k \geq t} r_k$。它们可以共享相同的基础模型与头的维度，但*语意与监督管线*不同：ORM 是从固定标签离线训练的，而价值函数是 on-policy 训练的，并用于计算策略梯度（policy gradients）的优势 $A_t = \hat{R}_t - V_t$。

### 5.7.1 各类奖励模型的推论方式（Inference Across Reward Model Types）

这些模型在推论时（即训练完成后）处理数据的方式不同，以应对 RM 所服务的一系列任务。

**Bradley-Terry RM（偏好模型）：**

- *输入：* 提示 $x$ + 候选补全 $y$
- *输出：* 透过线性层从 EOS／最后 token 隐藏状态得到的单一标量 $r_\theta(x, y)$
- *用途：* 对 $k$ 个补全重新排序、选出第一名（best-of-N 采样）；或为 RLHF 提供终端奖励
- *汇总方式：* 标量输出不需要汇总

**结果 RM（Outcome RM）：**

- *输入：* 提示 $x$ + 补全 $y$
- *输出：* 补全 token 上的逐 token 概率 $p_t \approx P(\text{在 token } t \text{ 处正确})$
- *用途：* 为完成的候选答案评分；透过平均、最小值（尾部风险）或乘积 $\prod_t p_t$（等价地，对数概率总和 $\sum_t \log p_t$）进行汇总
- *汇总选项：* 平均正确性、最小 $p_t$、对最后 $m$ 个 token 取平均，或当任一 $p_t < \tau$ 时触发门槛标记

**过程 RM（Process RM）：**

- *输入：* 提示 $x$ + 带有步骤边界的推理轨迹
- *输出：* 步骤边界处的分数（例如正确／中性／错误的类别 logits）
- *用途：* 为完成的思维链评分；或透过修剪低分分支来引导搜索／解码
- *汇总方式：* 在步骤层级（而非 token 层级）——平均步骤分数、最小值（快速失败），或偏重后段步骤的加权总和

**价值函数（Value Function）：**

- *输入：* 提示 $x$ + 当前前缀 $y_{\leq t}$（一个状态）
- *输出：* 补全中每个 token 位置的 $V_t$（从状态 $t$ 起的期望剩余回报）
- *用途：* 在 RL 训练期间计算逐 token 优势 $A_t = \hat{R}_t - V_t$；每一步的价值作为基线（baseline）
- *汇总方式：* 通常取最后生成 token 处的 $V$；其诠释与「正确概率」不同

总结来说，理解这些不同模型的方式是：

- **RM：**「这整个答案有多好？」→ 标量值
- **ORM：**「哪些部分看起来正确？」→ 逐 token 正确性
- **PRM：**「推理步骤是否合理？」→ 逐步骤分数
- **价值函数：**「从这里开始还剩多少奖励？」→ RL 优势的基线

## 5.8 生成式奖励建模（Generative Reward Modeling，又称 LLM-as-a-judge）

由于偏好数据的成本高昂，一个庞大的研究领域应运而生：使用现有语言模型作为人类偏好的评审，或用于其他评估情境 [78]。其核心想法是以「如何评判」的说明、一个提示以及两个补全来提示语言模型（就像人类标注者的做法一样）。以下是一个范例提示，来自此领域的开创性工作之一——聊天评估 MT-Bench [78]：

```
[System]
Please act as an impartial judge and evaluate the quality of the responses provided by
two AI assistants to the user question displayed below.
You should choose the assistant that follows the user's instructions and answers the
user's question better.
Your evaluation should consider factors such as the helpfulness, relevance, accuracy,
depth, creativity, and level of detail of their responses.
Begin your evaluation by comparing the two responses and provide a short explanation.
Avoid any position biases and ensure that the order in which the responses were
presented does not influence your decision.
Do not allow the length of the responses to influence your evaluation.
Do not favor certain names of the assistants.
Be as objective as possible.
After providing your explanation, output your final verdict by strictly following this
format: "[[A]]" if assistant A is better, "[[B]]" if assistant B is better, and "[[C]]"
for a tie.
[User Question]
{question}
[The Start of Assistant A's Answer]
{answer_a}
[The End of Assistant A's Answer]
[The Start of Assistant B's Answer]
{answer_b}
[The End of Assistant B's Answer]
```

鉴于 LLM-as-a-judge 在评估上的效力——它催生了许多其他评估，例如 AlpacaEval [79]、Arena-Hard [80] 与 WildBench [81]——许多人开始使用 LLM-as-a-judge 而非奖励模型来建立与使用偏好数据。

一整个研究领域围绕着如何使用所谓的「生成式奖励模型」（Generative Reward Models）而兴起 [82] [83] [84]（包括*专门*被训练成有效评审的模型 [85]），但在 RM 评估上，它们往往落后于现有的奖励模型，这显示奖励建模对当前的 RLHF 而言仍是一项重要技术。

提升 LLM-as-a-judge 工作流程稳健性的一个常见技巧，是使用采样温度 0 来降低评分的变异。

## 5.9 延伸阅读（Further Reading）

奖励建模的学术文献在 2024 年确立。早期进展大多集中在建立基准测试（benchmarks）与辨识行为模式。第一个 RM 基准测试 RewardBench 为测试奖励模型提供了共通的基础设施 [86]。自那以后，RM 评估已扩展到与一般后训练模型可用的评估类型相似的范畴，其中一些评估测试在已知真实答案的领域上的预测准确度 [86]，另一些则更接近以 LLM-as-a-judge 进行的「感觉」（vibes）式评估或与其他基准测试的相关性 [87]。

新基准测试的例子包括：

- **纯文字（一般聊天／偏好）：** RMB [88]、RewardBench2 [89]、Preference Proxy Evaluations [90]，或 RM-Bench [91]。
- **专门的纯文字（数学等）：** 多语言奖励基准（M-RewardBench）[92]、针对检索增强生成（retrieval augmented generation, RAG）的 RAG-RewardBench [93]、针对错字的 ReWordBench [94]、RewardMATH [95]，或 AceMath-RewardBench [96]。
- **过程 RM：** PRM Bench [97] 或 ProcessBench [98]，以及视觉基准 VisualProcessBench [99] 或 ViLBench [100]。
- **代理型 RM：** Agent-RewardBench [101] 或 CUARewardBench [102]。
- **多模态：** MJ-Bench [103]、Multimodal RewardBench [104]、VL RewardBench [105]，或 VLRMBench [106]。

要了解*训练*奖励模型的进展，可以参考新的奖励模型训练方法，包括面向条件化模型（aspect-conditioned models）[107]、高质量人类数据集 [108] [109]、扩展性实验 [30]、大规模实验 [49]，或数据去偏（debiasing data）[110]。
